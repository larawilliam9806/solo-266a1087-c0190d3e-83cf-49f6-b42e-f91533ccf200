# 变异归一化汇总平台

同一次插入/缺失在重复序列中可能被不同样本写成不同坐标。本平台接收参考序列与
逐样本 TSV 变异文件，将等价变异按参考**左对齐归一化并去冗余**，再按规范变异
汇总多样本检出情况。

技术栈：Flask + SQLite（WAL），Docker Compose 一键启动。

## 快速启动

```bash
docker compose up -d --build
# 打开 http://localhost:8000
```

SQLite 数据文件存放在命名卷 `variant-data`（容器内 `/data/variants.db`），
重建容器不丢数据；`SECRET_KEY` 请在 `docker-compose.yml` 中替换为生产密钥。

本地开发：

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
DATABASE_PATH=/tmp/dev.db flask --app 'app:create_app()' run --debug
```

## 使用流程

1. **先上传参考序列**：一条仅含大写 `A/C/G/T` 的序列，支持纯文本或单记录 FASTA。
2. **逐样本上传 TSV**：Tab 分隔、1-based 坐标，可带表头：

   ```tsv
   POS	REF	ALT	GT
   3	T	TT	0/1
   8	A	C	1/1
   ```

   - 仅接收：单碱基替换、带锚碱基的纯插入（如 `T>TT`）、带锚碱基的纯缺失（如 `TT>T`）
   - GT 允许 `0/1`、`1/1`；**单碱基替换还允许 `0/0`**：表示该位点已检测但未检出
     所列 ALT（即纯合参考）。`0/0` 行同样必须通过 REF 核对与归一化重复记录校验，
     插入/缺失行不允许 `0/0`
   - 每行先核对 REF 与当前参考是否一致，再做左对齐归一化
3. 首页按**规范变异**列出检出样本数（`0/0` 不展示、不计数）；点详情查看各样本
   基因型与原始位点（同样只含检出记录）。
4. 在首页「三联核查」卡片选择当前参考下**三个不同的有效样本**分别作为父亲、
   母亲、子代，对三份样本中出现的全部单碱基位点做亲子遗传核查。

## 三联核查（双亲 + 子代）

- **核查范围**：三份样本中出现的全部单碱基替换位点（插入/缺失不参与）；
  `0/0` 是「已检测」的位点证据，纯 `0/0` 样本也能作为核查方。
- **判定规则**（对三方记录齐全、且三方在该位点只有一种 ALT 的位点）：
  子代的两个等位基因必须能由父亲、母亲**各传一个**组合得到，否则列为
  「无法解释的位点」，并列出三方 GT。
- **单独列出、不做遗传判断的位点**：
  - 任何一方缺少该位点记录 → 注明缺席的角色与样本；
  - 三方记录中出现两个及以上不同 ALT（多等位基因，含 `0/0` 行申报的 ALT）
    → 注明出现的 ALT 数量与种类。
- **一致性保证**：一次核查在单个快照事务内完成，只读取**同一时刻、同一版
  参考**下的有效数据。样本重传或参考重验后再次提交即使用当前数据；所选样本
  已被删除/重传（id 失效）或重验后变为待重传时，页面提示重新选择。失败的
  上传整体回滚，原有核查依据不受影响。

## 关键规则

### 归一化（参考左对齐）

采用经典 left-align 流程（与 `bcftools norm` / `vt normalize` 等价）：

1. 去除 REF/ALT 共同后缀；
2. 无法去尾时整体左移一位并补参考前缀碱基，循环直到不能移动；
3. 在参考起点出现空等位基因时回退到最后一个合法带锚状态；
4. 去除共同前缀（每个等位基因至少保留 1 个锚碱基）。

因此重复序列中的等价写法（如 `GCTTTGC` 上 `(3,T,TT)`、`(4,T,TT)`、`(5,T,TT)`）
都会归一化为同一个规范键 `(2,C,CT)`，从而被识别为同一变异。

### 事务与一致性

- 同一样本归一化后出现重复变异（同一规范键，含 `0/0` 与检出记录冲突）→
  **整份文件拒绝**，不写入任何数据。
- 任何校验错误（REF 不符、非法 GT、类型不支持、格式错误等）都在事务内失败回滚，
  **错误上传不改变当前结果**。
- 同名样本重传 = 替换：新文件完整校验通过后，旧变体在同一事务中删除，旧变异不再计数。
- 更换参考 = 在一个写事务内插入新参考并**重验全部样本**：
  REF 不符或归一化后重复的样本标记为 `NEEDS_REUPLOAD`（待重传）、变体删除、
  从汇总剔除；修正后重新上传即恢复。
- 所有写事务使用 `BEGIN IMMEDIATE` 立即取 SQLite 写锁，使样本上传与参考更新
  严格串行；页面读取与三联核查使用快照事务，因此样本上传与参考更新交错时，
  页面只会展示 **同一版参考下的完整汇总**，一次核查也只会使用同一时刻、
  同一版参考的有效数据，不会出现跨版本混算。

### `0/0` 记录的处理

- 仅单碱基替换行可填写 `0/0`，语义为「该位点已检测、未检出所列 ALT」（纯合参考）；
  仍须通过 REF 核对与归一化重复记录校验，因此只含 `0/0` 的样本也是有效样本。
- `0/0` 记录写入数据库并参与三联核查，但首页规范变异汇总、检出样本数与
  变异详情只统计/展示 `0/1`、`1/1` 的检出记录；样本列表同时展示
  「检出变异数」与含 `0/0` 在内的「检测记录数」。

## 目录结构

```
app/
  __init__.py        # Flask 工厂与路由
  normalization.py   # 纯函数：解析、校验、左对齐归一化（无 Flask 依赖）
  trio.py            # 纯函数：三联 SNP 位点分类与孟德尔遗传判定（无 Flask 依赖）
  db.py              # SQLite 连接、WAL、事务、建表
  services.py        # 上传/重验/替换/汇总/三联核查业务逻辑
  templates/         # Jinja2 页面（含 trio.html 核查结果页）
  static/style.css
tests/               # unittest：归一化单测、随机性质测试、三联纯函数/端到端、并发、集成
docker/entrypoint.sh
Dockerfile
docker-compose.yml
```

## 测试

```bash
python -m unittest discover -s tests -v
```

- `test_normalization.py`：解析、边界、等价变异左对齐、重复拒绝、`0/0` 规则等
- `test_properties.py`：4000 个随机变异，验证「单倍型保持」「同事件同规范键」
- `test_trio.py`：孟德尔判定真值表、缺记录/多 ALT 分类、`0/0` 位点处理
- `test_trio_app.py`：三联核查端到端流程（违规/排除/可解释分类、重传与参考
  重验后的快照一致性、失效样本提示重选、纯 `0/0` 样本参与核查）
- `test_app.py`：Flask 端到端流程（上传、替换、换参考重验、错误隔离、删除）
- `test_concurrency.py`：上传与参考轮换交错时的快照一致性

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 参考信息、上传表单、样本列表、三联核查表单、规范变异汇总 |
| POST | `/reference` | 上传/更换参考（multipart 字段 `reference`） |
| POST | `/samples` | 上传/重传样本（字段 `name`、`sample`） |
| POST | `/samples/<id>/delete` | 删除样本 |
| POST | `/trio-check` | 三联核查（字段 `father`、`mother`、`child`，均为样本 id） |
| GET | `/variants/<pos>/<REF>><ALT>` | 变异详情：样本、GT、原始位点（仅检出记录） |
| GET | `/healthz` | 健康检查 |
